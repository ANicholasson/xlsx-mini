# Performance is a design input with measured, ratcheting budgets

The hot path (cell normalisation, escaping, interning, style lookup, part assembly, CRC, compression) follows fixed rules: one pass over rows, each row encoded into a byte sink as soon as it is built so a sheet never exists as one string, precomputed column letters, slice-by-8 CRC tables built once, an escape fast path that scans char codes and copies only when needed, no regular expressions or per-cell closures or objects, and the async boundary only at compression. Benchmarks live in the repository and run on every pull request on GitHub's runners, in Node, Bun and Deno; the result is one comment on the pull request with a table of changes and two charts GitHub draws inline, and a push to `main` records the run on a history branch that feeds a chart the README shows. Shared runners are noisy, so changes inside ten percent are labelled noise and the job never gates a merge. CodSpeed was tried first and dropped: its simulation leaves zlib out of the measure, and a hosted dashboard behind a GitHub App is more than this project wants. Budgets are set from the first measured baseline and only ratchet down.
