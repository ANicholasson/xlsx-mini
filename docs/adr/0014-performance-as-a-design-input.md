# Performance is a design input with measured, ratcheting budgets

The hot path (cell normalisation, escaping, interning, style lookup, part assembly, CRC, compression) follows fixed rules: one pass over rows, each row encoded into a byte sink as soon as it is built so a sheet never exists as one string, precomputed column letters, slice-by-8 CRC tables built once, an escape fast path that scans char codes and copies only when needed, no regular expressions or per-cell closures or objects, and the async boundary only at compression. Benchmarks live in the repository and run on every pull request on GitHub's runners, in Node, Bun and Deno. The pull request and `main` are built and timed on the same runner in the same process, call by call in turns, and the minimum of each is compared, because noise only adds time and the difference between two runners is far larger than the difference between two runs; the result is one comment with a table per runtime. Changes inside five percent are labelled noise and the job never gates a merge. An earlier version compared against numbers recorded on `main` by a previous run and showed forty-percent swings on changes that touched nothing; that is why the comparison moved onto one machine. CodSpeed was tried first and dropped: its simulation leaves zlib out of the measure, and a hosted dashboard behind a GitHub App is more than this project wants. Budgets are set from the first measured baseline and only ratchet down.
