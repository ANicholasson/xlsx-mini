The writer escapes the places where every application that shows them reads the escape: shared cell text, a formula's cached text, and validation titles and messages. A formula's cached text matters only to a reader that does not calculate, because all three applications calculate on open. The writer escapes inline cell text too, because Excel and LibreOffice read the escape there. Numbers shows the escape in inline text, so a stream meant for Numbers takes `strings: "shared"`. Every other place keeps its text as before. Escaping it would trade one application's reading for another's, and a sheet name also stands inside formulas, where only Excel reads the escape.

Numbers reads the escape in its own way. It takes each `_x` as the start of a piece and the next underscore as the end of that piece, and it decodes a piece only when the piece is `_xHHHH_`. After an `_x` that is not an escape, it therefore takes the underscore of the next escape as an end. It read `_x_x005F_x0041_`, the form the standard gives for `_x_x0041_`, as `_x_x005FA`. So the writer keeps the underscore of text that looks like an escape and writes its `x` as `_x0078_`: `_x0041_` becomes `__x0078_0041_`. No application can take the kept underscore as the start of an escape, because another underscore follows it. From shared strings, Excel and Numbers read seven such texts and 338 named and generated ones as written. LibreOffice reads them as written too, apart from the line breaks described above.

In the places it escapes, the writer writes a carriage return as the character reference `&#13;`, which XML does not turn into a line feed. Excel and Numbers keep it in shared and inline text, and LibreOffice keeps it in a text without a line feed. In a validation message, where XML would turn a raw carriage return into a space, Excel keeps it and LibreOffice shows a line break. Every other place writes a carriage return as itself, as before. Excel repairs a file whose formula holds `&#13;` and drops the formula, while it computes `A1+` CR `B1` written as itself, which XML reads as `A1+` LF `B1`.
